## Context

THORChain operates as a supra-national entity run by Node Operators, delivering features for users. Anyone can submit changes to the protocol, but it must respect the Protocol's Constitution - an assertion of how the protocol should be run. Changes to the protocol which do not alter the constitution are valid and can be submitted at any time. Changes to the protocol which alter the constitution must be brought to the network via an Architectural Design Record. Nodes can reject new software updates on the principle they breach the Constitution. 

Users must respect the Constitution, any action which breaches the Constitution can be brought to relief by Nodes by any means possible granted by this Constitution. 

## Decision

The THORCHAIN Constitution has been accepted by 100% as of the Nodes on the Network as of the Acceptance Date. 

## Constitution

# 1. Nodes
1.1* The protocol is operated by Nodes. Nodes must unanimously agree on the software to run at any time by way of network upgrades.  
1.2* No other individual or entity can change, alter, or otherwise intervene the Network's operation.
1.3* Nodes are not required to be identified by the protocol; they must simply meet Minimum Bond requirements. 
1.4* Nodes are sovereign entities and reserve the right to act in any way, but they are subjected to the terms of the Network. 
1.5* The Network must ensure that best efforts are maintained to preserve Security over Secured Assets. 
1.6* THe Network will give no priority to any Node.
1.7* The Network will churn (re-generate vaults and rotate the Validator Set) on a regular cycle and eject Nodes based on Performance, Age and Bond. 
1.8* The Network may choose to reject a node for running an outdated Ruleset. 

# 2. Users
2.1* Every transaction thorugh the Network must pay a fee.
2.2* Every transaction through the Network must be no more than the value of the input transaction, minus the fee, considering the entire lifespan of the transaction. 
2.3* Nodes reserve the right to ignore or reject a transaction which breaches the Constitution. 

# 3. Developers
3.1* Any developer can choose to submit feature requests to the protocol. 
3.2* Features that do not change the Constitution nor alter Network Operations can be considered at any time. 
3.3* Features that alter, change or add new Network Operations may be submitted via an Architectural Design Record (ADR).
3.4* Features that alter the Constitution must be submitted via an Architectural Design Record (ADR).
