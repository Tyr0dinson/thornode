# Curated security mutation check

Run `scripts/test-security-mutations.py --mode fast --summary /tmp/security-mutations.json` from any directory. The script reads the repository's `toolchain` directive, sets `GOTOOLCHAIN` to that version, limits Go to four processors and two package builds, and serializes the bounded suite through `/tmp/thornode-test-quality-build.lock`. It defaults to a dedicated writable Go cache under `/tmp`; set `GOCACHE` to reuse an existing writable cache. Go overlays replace one source file per command with a temporary copy; the checkout is never mutated. Temporary overlays are removed on exit.

The fast set exercises an on-chain supermajority boundary, signing halt activation, peer attestation signature verification and replay handling, and safe balance subtraction. `--mode deep` adds a chain halt boundary and impossible signer-count check. Each mutant has a single exact source anchor in `test-security-mutations.json` and a targeted independent assertion test. If an anchor changes or is ambiguous, the runner marks the mutant invalid. A mutant is killed only when a named test fails; build failures, missing tests, lock failures, and command timeouts remain separate outcomes. Any unexpected survivor, invalid mutant, timeout, or failed baseline causes a nonzero exit.

The weak quorum control runs a deliberately incomplete unanimity test against the same quorum boundary mutant. It must survive, while `TestSecurityMutationQuorumBoundary` must kill the mutant. This demonstrates that the runner does not count every mutation as killed and that the strengthened boundary assertions matter. The control is excluded from the killed count.

The JSON summary includes the baseline runs, every command and test outcome, the seed, execution budget, per-command timeout, toolchain, mutant counts, and output tails. The seed is fixed for reproducible manifest order; this curated suite does not use random mutation generation. Default bounds are 300 seconds per Go command, 600 seconds for the shared build lock, and 1800 seconds for the suite. Tune these with `--seconds-per-command`, `--lock-wait`, and `--budget-seconds` in constrained CI environments.

CI wiring: run the fast command as an independent targeted job and preserve the JSON summary as an artifact on success and failure. The optional deep mode is suitable for a slower scheduled job. The CI workspace owns any root Makefile or `.gitlab-ci.yml` changes.
